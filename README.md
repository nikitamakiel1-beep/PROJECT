# Conway Replicatio — Browser-Only Oracle Always Free Deployment

[![Deploy to Oracle Cloud](https://oci-resourcemanager-plugin.plugins.oci.oraclecloud.com/latest/deploy-to-oracle-cloud.svg)](https://cloud.oracle.com/resourcemanager/stacks/create?zipUrl=https://github.com/nikitamakiel1-beep/PROJECT/archive/refs/heads/conway-oci-deploy-v1.zip)

This Terraform stack creates a browser-managed, HTTPS-protected Conway Replicatio worker on an Oracle Cloud Always Free Ampere A1 instance. It requires no local terminal, SSH client, PowerShell, Docker installation, or Conway website account.

## What the stack creates

- one `VM.Standard.A1.Flex` instance fixed at 2 OCPUs and 12 GB RAM;
- a 100 GB persistent boot volume by default;
- an Oracle VCN, public subnet, internet gateway, and HTTPS-only network rules;
- Oracle's Bronze scheduled boot-volume backup policy when available;
- Caddy automatic HTTPS on an IP-derived `sslip.io` hostname;
- a protected, one-time browser bootstrap portal;
- a private Docker network containing:
  - the pinned original Conway Automaton plus Replicatio overlay;
  - Ollama with `qwen3:4b-instruct` local inference;
  - a deny-by-default local Conway compatibility service;
- persistent Agent Wallet and SQLite state under `/opt/conway-replicatio/data`;
- a bounded watchdog that restarts the Automaton child process and enters lockdown after a crash loop.

## Browser-only flow

1. Select **Deploy to Oracle Cloud**.
2. Sign in to Oracle and create the stack with **Run apply** enabled.
3. Wait for Apply to finish.
4. Reveal and open the sensitive `bootstrap_url` output.
5. In the protected portal, enter:
   - a fine-grained GitHub token belonging to `nikitamakiel1-beep`, restricted to `Conway-Replicatio`, Contents read-only;
   - a public EVM Creator address;
   - an agent name.
6. Wait for build, verification, local model download, wallet generation, checkpoint, and activation.
7. Copy the resulting worker URL and control token into `https://conway-replicatio.lovable.app/setup` → **Connect an existing worker**.
8. Seal the bootstrap portal after Lovable connects and the control token is stored safely.

## Initial safety profile

The first deployment is intentionally restrictive:

- children: `0`;
- child budget: `0`;
- transfers: `0`;
- X402 payments: `0`;
- purchases and domains: denied by the compatibility service;
- Creator Honey payouts: disabled;
- local inference cost: `0`;
- real Conway Cloud: disabled;
- external funding: not required and should not be added during validation.

The generated Agent Wallet is a separate wallet stored inside OCI persistent storage. The portal never asks for a seed phrase or private key.

## Security boundaries

- The bootstrap token is generated by Terraform and placed in the URL fragment, so browsers do not transmit it as part of the HTTP request URL.
- The GitHub token is verified, used through a temporary askpass file, overwritten, and deleted after cloning.
- The Creator value must be a public `0x` address.
- The worker control token is generated server-side and shown only in the protected portal until sealing.
- Ports 8080, 8081, 8787, and 11434 are not publicly exposed.
- The compatibility layer returns virtual non-spendable health credits and rejects mutating cloud/payment operations.
- A pre-activation checkpoint and SQLite integrity check are mandatory.
- Docker logs are rotated and API/log output is redacted.

## Honest limitations

- Oracle can report no Ampere A1 host capacity. Retry with availability-domain index 1 or 2.
- Always Free has no production SLA and Oracle can reclaim idle resources under its published policy.
- A 4B local model on two ARM OCPUs is free but slow and materially less capable than a commercial frontier model.
- The first private worker build can take 30-90 minutes.
- This standalone mode preserves the original continuous Automaton loop, wallet, SQLite memory, Colonial AI, products, policy controls and local execution, but disables Conway Cloud sandboxes, Conway paid inference, domain purchases, credit transfers and child creation.
- Do not fund the Agent Wallet until a separate live security and behavioural validation has passed.

## Destruction

Destroying the Resource Manager stack can destroy the VM and its wallet/state. Confirm that Oracle boot-volume backups exist before destroying. Never destroy the stack while funds remain in the Agent Wallet.
