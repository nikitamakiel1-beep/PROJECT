# Governed datasets and optional-model runtime

## Objective

Move from dependency-free reference algorithms to evidence-bearing candidate models without connecting production CRM data, downloading pretrained bases, or enabling any external action.

## Dataset classes

Only two source classes are accepted:

1. `synthetic` — deterministic fictional data generated by repository code.
2. `explicitly_approved` — separately reviewed data with documented purpose, minimisation, retention and lawful basis.

The current laboratory uses only synthetic data.

## Generated datasets

The generator creates three independent temporal datasets:

- CRM/B2B/B2C conversion records across industrial, service and professional segments.
- RAG knowledge units for IVA, CRM and IOP retrieval.
- Vision records for document, chart, logo, product, landscape and person-style geometric cards.

Train, validation and test partitions are chronological and record-disjoint. Each file, card and manifest receives a SHA-256 digest. An optional HMAC signing key may sign the manifest outside source control.

## Optional runtime

The reviewed CPU runtime is pinned under `requirements/optional-ml-cpu.txt` and `config/optional-ml-runtime.json`. The workflow runs offline after dependency installation:

- no model download;
- no dataset download;
- no external upload;
- no production credentials;
- no automatic promotion.

## Candidate pipelines

### LoRA language candidate

A tiny GPT-style transformer is created from configuration with random weights. It does not download a pretrained base. PEFT/LoRA adapters are attached to attention and projection layers; only adapter parameters train. Evaluation records train loss, validation loss, test perplexity and trainable-parameter fraction.

### Contrastive retrieval candidate

A PyTorch EmbeddingBag encoder learns a normalised latent space over synthetic knowledge units. The candidate is assessed by retrieval mean reciprocal rank against its random initialisation baseline.

### YOLO card candidate

The runtime generates geometric 96×96 images and YOLO labels from the governed vision manifest. Ultralytics builds a YOLO11 nano architecture from YAML with `pretrained=False`, trains for a bounded number of CPU epochs and evaluates mAP50, precision and recall.

### Quantisation

ONNX Runtime dynamic int8 quantisation records file size, CPU latency, speed-up and relative output error. More than 5% relative quality loss blocks review.

## Evidence gate

Every candidate produces a shadow evidence pack with:

- dataset and code digests;
- seed and framework;
- metrics and transparent baselines;
- segment metrics;
- quantisation metrics;
- privacy, memorisation, prompt-injection, reward-hacking and extraction tests;
- rollback artifact;
- limitations.

The gate may mark a candidate eligible for human review. It can never promote or deploy it.

## Execution

Generate datasets locally:

```bash
python scripts/run_optional_candidate_lab.py generate
```

Install the isolated runtime and run one candidate:

```bash
python -m venv .venv-ml
. .venv-ml/bin/activate
pip install -r requirements/optional-ml-cpu.txt
python scripts/run_optional_candidate_lab.py embedding
```

The GitHub workflow `Optional ML candidate laboratory` is manual-only and uploads short-lived evidence artifacts.

## Safety boundary

- No client-derived training data.
- No personal fields.
- No pretrained model download.
- No network retrieval during training.
- No automatic CRM, Linear, messaging, proposal, invoice, contract or payment action.
- No automatic model promotion.
- Stage 003 provider-runtime gate remains independent and open.
